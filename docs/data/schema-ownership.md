# Database Schema Authority & Ownership

> **Document Metadata**:  
> `Status: Draft` | `Owner: Database Engineering / Lead Architect` | `Last verified: Not verified` | `Evidence: Schema authority profile`

This document defines the schema authority profile, migration ownership, and deployment authority for database schemas.

---

## 1. Schema Authority Profile

The repository MUST operate under exactly ONE declared schema authority model:

- [ ] **Code-First / Migration-First (EF Core)**:
  - C# Entity Configurations and DbContext migrations are the authoritative source of truth.
  - Schema changes are generated via `dotnet ef migrations add` and applied via pipeline.
- [ ] **Database-First / SQL-First (Dapper / Flyway / DbUp)**:
  - Versioned `.sql` migration scripts in source control are the authoritative source of truth.
  - C# models are mapped to database tables; the database is never generated by ORM code.
- [ ] **Externally Managed Schema**:
  - The database schema is owned and deployed by an external team, legacy DBA pipeline, or shared platform.
  - This application is a schema consumer and MUST NOT execute DDL migrations.

*Rule: Ambiguous shared schema ownership is FORBIDDEN. If the profile is undeclared, infer from repository evidence and do NOT introduce an unapproved migration tool.*

---

## 2. Deployment Ownership & Permissions

| Environment | Who / What Applies Migrations? | Execution Boundary |
|---|---|---|
| **Local Development** | Developer CLI or automatic startup | Local container / instance |
| **CI / Test Pipelines**| CI Automated Runner | Isolated ephemeral database |
| **Staging / Production**| Dedicated CD pipeline with migration role | Controlled release window with backup |

*Security Guardrail: The runtime application service MUST NOT run with `DDL` (schema modification) permissions in production unless explicitly approved by architecture governance.*
